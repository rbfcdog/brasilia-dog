# NextWave Hackathon 2026 deliverables

_Artifacts required for the public submission at code freeze._

---

## Required artifacts

| Deliverable | Requirement |
| --- | --- |
| Presentation | Slides that support the pitch and technical defense |
| Demo | A live demo or video. The live system still matters because judges operate it during trial by fire |
| Public GitHub repository | Public repository with a README that someone who was not present can follow |
| Architecture diagram | PDF or PNG, 25 MB or less |
| Decision log | Markdown export of the flight log. It records real technical trade-offs as they are made |

## What the artifacts need to prove

| Artifact | What a reviewer should be able to see |
| --- | --- |
| Slides | Problem, chosen scope, core design choices, demo path, and the trade-offs behind the design |
| Demo | The selected challenge runs end to end and handles its required failure cases |
| Repository and README | How to understand and run the prototype from a clean start |
| Architecture diagram | Major components, data or control flow, trust boundaries, and the pieces involved in the live demo |
| Decision log | Alternatives considered, why a choice was made, and the consequence of each trade-off |

## Submission fields

Mission Control collects these fields:

- Public GitHub repository URL
- Slides URL
- Demo URL for a video or live demo
- Architecture diagram upload

See [Mission control](./mission-control.md) for the pre-flight checklist and [Decision log](./decision-log.md) for the Markdown record template.

## Delivery standard

The jury evaluates what runs in front of them. Slides or recorded claims do not replace a working demo, a public repository, or a system that reacts correctly when a judge changes live input.
