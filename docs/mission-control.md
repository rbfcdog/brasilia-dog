# NextWave Hackathon 2026 mission control

_Payload fields, flight-log rules, and the pre-flight readiness checklist from Participant HQ._

---

## Payload

Mission Control is the official submission area. Its contents lock at code freeze.

| Field | Requirement |
| --- | --- |
| GitHub repository URL | Public repository URL |
| Slides URL | Link that judges can open without login |
| Demo URL | Video or live-demo link |
| Architecture diagram | PDF or PNG, 25 MB or less |

## Flight log

The flight log is the team’s decision log. Record each real trade-off when the team makes it, then export it to Markdown for the public repository. The jury reads it.

Participant HQ currently shows no flight-log entries. That is a status snapshot, not a recommendation to leave the log empty. The pre-flight checklist requires at least three real trade-offs.

Use [Decision log](./decision-log.md) as the repository template.

## Pre-flight checklist

| Check | Done |
| --- | --- |
| Public GitHub repository has a README that someone who was not present can follow | [ ] |
| Demo runs from a clean start without someone touching the keyboard | [ ] |
| Architecture diagram is uploaded as a PDF or PNG | [ ] |
| Decision log records at least three real trade-offs | [ ] |
| The selected brief’s ugly cases are handled explicitly | [ ] |
| Trial by fire is rehearsed with a live judge change and correct system reaction | [ ] |
| Slides link works without login and the pitch is rehearsed within time | [ ] |

## Crew card and readiness

Participant HQ displays pre-flight readiness as a percentage. Treat the checklist as the source for that status. Do not mark an item complete until the team has verified it.
